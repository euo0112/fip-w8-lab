## 一、研讨一：SSH 密钥与 GitHub

### 1.1 任务要求

前置条件：W8 已会用 HTTPS 方式完成 `git add / commit / push`。

本研讨要求：

1. 生成个人密钥对（每人自己的，勿共用）；
2. 认清公钥与私钥两个文件，明确哪个可以外发、哪个绝对不行；
3. 把公钥添加到 GitHub 账号，并在本机用 `ssh -T git@github.com` 验证；
4. 把本地仓库的 remote 从 `https://` 改为 `git@` 形式，并用 SSH 完成一次推送。

### 1.2 操作过程

#### 第 1 步：生成密钥对

```bash
ssh-keygen -t ed25519 -C "3482****@qq.com"
```

- 算法选 `ed25519`：密钥短、签名快，且 GitHub 全版本支持；
- 保存位置采用默认值，即 `~/.ssh/id_ed25519`；
- 为私钥设置了口令（passphrase），避免私钥文件被拷走后可直接使用。

生成后目录下多出两个文件：

```
~/.ssh/
├── id_ed25519      私钥（464 字节，权限 600）
└── id_ed25519.pub  公钥（99 字节，权限 644）
```

#### 第 2 步：认文件（公钥 vs 私钥）

| 文件 | 开头内容 | 行数 | 能否外发 |
| --- | --- | --- | --- |
| `id_ed25519.pub` | `ssh-ed25519 AAAAC3NzaC1lZDI1NTE5...` | 单行 | **可以**，本来就要交给 GitHub |
| `id_ed25519` | `-----BEGIN OPENSSH PRIVATE KEY-----` | 多行 | **绝对不行**，不提交、不截图、不发群 |

判断口诀：**带 `.pub` 后缀的、单行的、`ssh-ed25519` 开头的，是公钥；没有后缀的、多行的、`BEGIN OPENSSH PRIVATE KEY` 开头的，是私钥。**

#### 第 3 步：添加到 GitHub 并验证

在 GitHub 的 *Settings → SSH and GPG keys → New SSH key* 中：

- **Title**：`MacBook Pro`（仅用于自己辨认，与密钥内容无关）
- **Key type**：`Authentication Key`（用于 git 认证；签名用途另选 Signing Key）
- **Key**：粘贴公钥**整行内容**，包含开头的 `ssh-ed25519` 算法标识

随后在本机验证：

```bash
ssh -T git@github.com
```

#### 第 4 步：remote 改为 SSH 并推送

```bash
git remote -v
# origin  https://github.com/euo0112/fip-w8-lab.git (fetch)
# origin  https://github.com/euo0112/fip-w8-lab.git (push)

git remote set-url origin git@github.com:euo0112/fip-w8-lab.git

git remote -v
# origin  git@github.com:euo0112/fip-w8-lab.git (fetch)
# origin  git@github.com:euo0112/fip-w8-lab.git (push)

git push
```

> 注：`git remote set-url` 执行成功时**没有任何输出**，这是 Unix 的惯例（无消息即成功），需要用 `git remote -v` 复核。

退出码为 `0`。`Everything up-to-date` 表示本地与远程完全一致、没有可推送的新提交；由于该命令已经完整走完 SSH 握手与认证流程，因此可以作为「SSH 推送通道可用」的证据。若需看到实际数据传输日志，可在有新提交时推送，输出形如：

### 1.5 遇到的问题与排查

| 阶段 | 现象 | 原因 | 处理 |
| --- | --- | --- | --- |
| 生成密钥后登录 | 设了口令，但未加入 ssh-agent，之后仍反复要求输入口令 | 口令只保护私钥文件，agent 里没有缓存 | 执行 `ssh-add --apple-use-keychain ~/.ssh/id_ed25519` 并把口令存入钥匙串，后续自动复用 |
| 首次连接 GitHub | 提示 `The authenticity of host 'github.com' can't be established` | 本机 `known_hosts` 中尚无 GitHub 主机公钥 | 核对指纹后输入 `yes` 接受，记录写入 `~/.ssh/known_hosts` |
| 修改 remote 后 | 命令无任何输出，误以为失败 | `set-url` 成功时本就静默 | 用 `git remote -v` 复核地址 |
| 推送时 | 若 remote 仍是 `https://`，会反复要求输入账号密码 | `https://` 走账号口令认证，`git@` 走密钥认证 | 用 `git remote -v` 确认地址以 `git@` 开头 |

任务单给出的两条排查线索在实际操作中得到验证：

1. **`Permission denied (publickey)`** —— 首先检查公钥是否**整行**粘贴（漏掉 `ssh-ed25519` 前缀或混入换行都会失败）；
2. **仍然要求输入密码** —— 用 `git remote -v` 检查 remote 是否还是 `https://` 形式。

本次排障中额外确认了一点：当 agent 中没有私钥时，`ssh -v` 会先出现 `Server accepts key`（服务器认可这把公钥），紧接着才因无法签名而 `Permission denied`。这说明问题出在**本地签名环节**，而非公钥未上传，可以据此快速定位。

### 1.6 安全约定

- 私钥 `id_ed25519` **从未**出现在任何提交、截图或群聊中；
- 仓库 `.gitignore` 中已排除 `id_ed25519`、`id_rsa`、`id_ecdsa`、`*.pem`，防止误提交；
- 报告中出现的邮箱做了脱敏处理；
- 公钥与指纹属于可公开信息，不构成风险。
